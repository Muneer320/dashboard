## **1\. Project Objective**

The **User & Event Dashboard** serves as the central interface for participants in the Ascent Techfest. It enables seamless onboarding, event discovery, participation tracking, and interaction through a unified system.

The goal is to create a **real-time, scalable, and user-centric platform** that integrates identity, events, and gamified interactions into one cohesive experience.

---

## **2\. Technical Stack**

| Component | Technology | Purpose |
| ----- | ----- | ----- |
| Frontend | Next.js (React) | Dashboard UI, onboarding, event pages |
| Backend | Node.js / API Routes | Business logic & API handling |
| Database | Supabase (PostgreSQL) | User data, events, submissions |
| Auth | Unstop \+ JWT | Identity sync & authentication |
| Realtime | Supabase Realtime | Live metrics & updates |
| QR System | Custom QR \+ Scanner | Event validation & tracking |

---

## **3\. Functional Requirements**

### **3.1 Dashboard Onboarding & Login**

* Integration with **Unstop** for authentication.  
* Redirect-based login flow:  
  * User logs in via Unstop  
  * Receives unique identifier (UID)  
  * UID synced with internal database  
* First-time onboarding:  
  * Basic profile creation (Name, Email, UID)  
  * Optional metadata (college, interests)

**Key Features:**

* Persistent login sessions  
* Identity synchronization across all modules  
* Secure token-based authentication

---

### **3.2 Dashboard Home**

* Overview of:  
  * Registered events  
  * Progress status  
  * Points / rewards (Sidequest integration)  
* Live metrics:  
  * Event participation  
  * Completion status  
  * Leaderboard snapshot

---

### **3.3 Events Page**

* Centralized listing of all events:  
  * Filters (category, type)  
  * Search functionality  
* Each event card includes:  
  * Title, description, timing  
  * Participation status  
  * CTA (Register / Enter / View)

---

### **3.4 Event Info & Internal Pages**

Each event has a **dedicated page/tab system**:

**Tabs include:**

* Overview  
* Rules  
* Submissions  
* Leaderboard (if applicable)

**Features:**

* Dynamic routing (`/events/[eventId]`)  
* Submission interface (file upload / link submission)  
* Real-time updates (status, deadlines)

---

### **3.5 Centralized QR-Based System**

* Unique QR codes for:  
  * Event entry  
  * Checkpoints  
  * Task validation

**Flow:**

1. QR scanned via dashboard/mobile  
2. Request sent to backend  
3. Validation logic checks:  
   * User eligibility  
   * Event status  
4. Response updates:  
   * Attendance  
   * Progress  
   * Rewards (Sidequest)

**Use Cases:**

* Event check-ins  
* Campus tour checkpoints  
* Sidequest triggers

---

## **4\. System Architecture & Data Flow**

1. **Authentication Phase**  
   * User logs in via Unstop  
   * UID stored in Supabase  
2. **Dashboard Load**  
   * Fetch user data, events, progress  
3. **Event Interaction**  
   * User joins event → DB updated  
   * Submissions stored & validated  
4. **QR Interaction**  
   * Scan → API validation → DB update  
5. **Realtime Updates**  
   * Supabase pushes updates to frontend

---

## **5\. Security & Data Handling**

* JWT-based authentication for all APIs  
* Role-based access control (admin/user)  
* Rate limiting on QR scans  
* Secure storage of submissions (signed URLs)  
* Input validation for all forms
