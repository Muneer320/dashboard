## USERS TABLE

Scalar columns:

| Column                  | Type                        | Notes                                  |
| ----------------------- | --------------------------- | -------------------------------------- |
| id                      | UUID PK                     | `gen_random_uuid()`                    |
| unstop_id               | varchar(128) UNIQUE         | nullable                               |
| username                | varchar(64) UNIQUE NOT NULL | used for login                         |
| password_hash           | varchar(255) NOT NULL       | bcrypt                                 |
| name                    | varchar(255) NOT NULL       |                                        |
| details                 | JSONB                       | profile extras (see below)             |
| events                  | JSONB                       | per-event registration map (see below) |
| food                    | JSONB                       | `{meal1,meal2,meal3: bool}`            |
| is_attending            | boolean                     | campus gate entry scanned              |
| is_profile_complete     | boolean                     |                                        |
| cents                   | integer                     | in-event currency                      |
| created_at / updated_at | timestamptz                 | auto-managed                           |

> `access_level` and `role` enum columns were dropped in migration 009.
> `team_id` was also dropped in migration 009 (may still exist if that migration was not applied).

## users.events JSONB (CRITICAL)

Keyed by event UUID. Each entry:

```json
{
  "<event_uuid>": {
    "isAttending": true,
    "restricted": false,
    "registered_at": "<ISO timestamp>",
    "submission": {
      "phase1": {
        "submitted": true,
        "submitted_at": "<ISO timestamp>",
        "answers": [{ "question_id": "q1", "answer": "my answer" }]
      },
      "phase2": {
        "submitted": false,
        "submitted_at": null,
        "answers": []
      }
    }
  }
}
```

> Migration 021 reshaped this from the old `{ repoLink, deployLink, submittedAt }` flat shape.

## events.rounds JSONB

```json
{
  "phase1": {
    "title":       "Round 1 — Ideation",
    "description": "...",
    "start_time":  "<ISO>",
    "end_time":    "<ISO>",
    "is_active":   true,
    "is_locked":   false
  },
  "phase2": { ... }
}
```

`is_active = true` + `is_locked = false` → submission window open.  
`is_locked = true` → phase closed by organizer.  
Both false → upcoming.

## events.questions JSONB

Added in **migration 021**. Keyed by phase, each value is an ordered array of
`QuestionDefinition` objects:

```json
{
  "phase1": [
    {
      "question_id": "q1",
      "question_text": "Describe your idea.",
      "question_type": "text",
      "required": true,
      "word_limit": 50
    },
    {
      "question_id": "q2",
      "question_text": "GitHub repo URL",
      "question_type": "url",
      "required": true
    },
    {
      "question_id": "q3",
      "question_text": "Track",
      "question_type": "mcq",
      "options": ["AI / ML", "Web Dev", "Mobile", "Open Innovation"],
      "required": true
    },
    {
      "question_id": "q4",
      "question_text": "Declarations",
      "question_type": "declaration",
      "declarations": ["This is original work.", "I agree to the rules."],
      "required": true
    }
  ]
}
```

Supported `question_type` values: `text`, `text-long`, `url`, `email`, `numeric`, `mcq`, `multi-choice`, `declaration`.

## events.participants JSONB

```json
{
  "<user_uuid>": {
    "name": "Alice",
    "isAttending": true,
    "restricted": false,
    "registered_at": "<ISO>",
    "submission": {
      "phase1": {
        "submitted": true,
        "submitted_at": "<ISO>",
        "answers": [{ "question_id": "q1", "answer": "my answer" }],
        "score": null,
        "feedback": null
      }
    }
  }
}
```

`score` and `feedback` are written by admins after judging; `answers` are written by the participant at submission time.

---

## IMPORTANT DESIGN DECISIONS

**Denormalization is intentional.**

- `users.events[eventId].submission` — latest snapshot, written first (recoverable on failure).
- `events.participants[userId].submission` — includes scoring slots (`score`, `feedback`).
- Always update both sides. User row first.

**Phase keys are always `phase1`, `phase2`, etc.** (lowercase, no spaces).
