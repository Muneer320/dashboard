# Backend Architecture

## Architecture Style

REST API — FastAPI, async, service-oriented. No ORM; plain dicts from the Supabase SDK are hydrated into dataclasses.

## Layer Responsibilities

| Layer           | Role                                                                       |
| --------------- | -------------------------------------------------------------------------- |
| `routes/`       | Parse HTTP request, call service, return response schema                   |
| `services/`     | Business logic, DB reads/writes, raises `HTTPException` on failure         |
| `models/`       | Dataclasses with `from_row()` factory and `to_insert()` payload builder    |
| `schemas/`      | Pydantic v2 models for request bodies and response shapes                  |
| `middleware.py` | JWT validation happens here **before** any FastAPI dependency runs         |
| `deps.py`       | `get_current_user`, `get_current_admin`, `get_admin_or_em`, `get_supabase` |

## Middleware: AccessControlMiddleware

Runs before FastAPI routing on every request:

- `/api/v1/admin*` → requires JWT with `role == "admin"`
- `/api/v1/qr*` or paths ending in `/participants` → requires `role in {Scanner, eventManager, admin}`
- All other `/api/v1/*` paths → requires any valid JWT (user or admin)
- Public paths (`/health`, `/docs`, `/auth/login`) → pass through

This means `app.dependency_overrides` in tests **cannot** bypass the middleware. Tests that hit protected paths must generate a real signed JWT.

## Core Modules

### Auth

- `POST /auth/login` → verifies bcrypt hash, issues user JWT
- `POST /auth/admin/login` → issues admin JWT with `role` claim
- `GET /auth/me` and `GET /auth/admin/me` for token introspection

### Events + Questions

- `GET /events` / `GET /events/{id}` — public-ish (requires user JWT)
- `POST /events/{id}/register` — dual-write to `users.events` + `events.participants`
- `GET /events/{id}/questions?phase=N` — returns typed question list for a phase
- `PUT /events/{id}/questions` — admin/EM sets questions (all phases at once)

### Submissions

- `POST /events/{id}/submit` — validates answers against question definitions, dual-writes
- `GET /events/{id}/submission?phase=N` — returns user's stored answers for a phase

### QR

- `POST /qr/scan` — `scan_type`: `collegeEntry | event | food`
- Rate-limited per IP + per token

### Admin Panel

- `GET /admin-panel/stats` — aggregate overview
- `GET /admin-panel/events/stats` — per-event breakdown
- `GET /admin-panel/participants` — filterable list
- `PATCH /admin-panel/participants/{uid}/restrict`
- `GET /admin-panel/my-events` — event manager scoped view
- `GET/POST/PATCH/DELETE /admin-panel/event-managers`

## Access Control Flow (Submission)

```
POST /events/{id}/submit
  → AccessControlMiddleware: valid JWT?
  → get_current_user dep: load User from DB
  → get_event: load Event from DB
  → validate_event_access():
      • users.events has eventId?           (registered)
      • entry.restricted != true?           (not banned)
      • event.rounds has phaseN?            (phase exists)
      • round.is_active AND NOT is_locked?  (window open)
  → get_questions_for_phase(): load question defs
  → _validate_answers(): type-check each answer
  → write users row (first)
  → write events row
```

## Error Handling

- All service errors raise `HTTPException` with appropriate status codes
- 422 for validation failures (wrong type, word limit exceeded, missing required answer)
- 403 for access control failures (not registered, restricted, phase not active)
- 404 for missing resources (event not found, no questions for phase)
- Middleware returns 401 for missing/invalid JWT, 403 for wrong role

## Testing

- `pytest` with `monkeypatch` — no real DB connection
- Supabase SDK calls are monkeypatched in all tests
- `AccessControlMiddleware` cannot be bypassed by `dependency_overrides`; tests that hit protected routes must generate real signed JWTs via `create_access_token()`
- 40 tests, all passing (`cd backend && uv run pytest`)
