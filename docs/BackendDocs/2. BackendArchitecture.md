# Backend Architecture

## Architecture Style

- REST-based backend
- Modular service-oriented design

---

## Folder Structure

/src
  /controllers
  /services
  /routes
  /middlewares
  /models
  /utils

---

## Responsibilities Breakdown

### Controllers
- Handle request/response
- Call services

### Services
- Core business logic
- DB interactions
- Validation

### Middlewares
- Auth (JWT)
- Role checks
- Rate limiting

---

## Core Modules

### 1. Auth Module
- Login
- JWT generation
- User validation

---

### 2. User Module
- Fetch/update user data
- Manage profile completion

---

### 3. Event Module
- List events
- Register users
- Manage participation

---

### 4. Submission Module
- Validate submissions
- Store files/URLs
- Update user + event

---

### 5. QR Module
- Validate scans
- Update attendance/food

---

## Access Control Engine (IMPORTANT)

All APIs must enforce:

1. Is user registered for event?
2. Is phase active?
3. Does user have correct accessLevel?

Failure → reject request

---

## Transactions

Every update affecting:
- users.events
- events.participants

MUST be wrapped in a transaction.

---

## Error Handling

- Standardized error responses
- No silent failures
