# API & Workflows

---

## AUTH

POST /auth/login

Flow:
- Validate credentials
- Return JWT

---

## EVENT REGISTRATION

POST /events/:id/register

Flow:
1. Check user exists
2. Check eligibility
3. Check capacity
4. Insert into:
   - users.events
   - events.participants

---

## SUBMISSION

POST /events/:id/submit

Flow:
1. Validate phase active
2. Validate accessLevel
3. Validate submission type
4. Store submission
5. Update both tables

---

## QR SCAN

POST /qr/scan

Input:
- userId
- mode (food/event)
- eventId (if event)

---

### FOOD FLOW

1. Check meal status
2. If already true → reject
3. Else → mark true

---

### EVENT FLOW

1. Check registration
2. Check accessLevel
3. Check duplicate entry
4. Mark attendance

---

## ACCESS VALIDATION (GLOBAL RULE)

Before any action:

- Is user registered?
- Is phase active?
- Does accessLevel match?

---

## IDENTITY FLOW

- Unstop → backend sync → DB
- First registration → credentials generated
- No duplicate credentials
