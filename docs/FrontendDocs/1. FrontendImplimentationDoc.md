# Frontend Implementation Guide — User & Event Dashboard

## 1. Objective

This document defines the complete frontend implementation for the User & Event Dashboard based on the provided Figma design.

The goal is to:
- Convert designs into production-ready UI
- Maintain consistency with backend architecture
- Enforce access control and event-phase logic at UI level
- Ensure scalable and reusable component structure

---

## 2. Tech Stack

- Framework: Next.js (App Router recommended)
- Styling: Tailwind CSS
- UI Components: ShadCN (or custom reusable components)
- State Management: React Query (preferred) or SWR
- Auth Handling: JWT (stored in HTTP-only cookies or local storage)

## 5. Core Concepts (VERY IMPORTANT)

### 5.1 Access Control

Frontend must respect backend rules:

Each event has:
- accessLevel: ROUND1 | FINAL | FULL
- phase: number
- status

### UI Rules:
- If not registered → show only overview
- If ROUND1 → only submission + status
- If FINAL → enable final round tabs
- Locked phases → disabled tabs

---

### 5.2 Phase-Based UI

Each event has multiple phases:

- Phase 1 → Qualifier
- Phase 2 → Final

UI must:
- Enable only active phase
- Disable future phases
- Show results only when available

---

### 5.3 Data Fetching Strategy

Use React Query:

- Cache user data globally
- Fetch events list
- Fetch event details on page load

---

## 6.1 Login Page (/login)

### Purpose
Authenticate user

### Components
- Input: Username
- Input: Password
- Button: Login

### Flow
1. User submits credentials
2. Call: POST /auth/login
3. Store JWT
4. Redirect to /dashboard

---

## 6.2 Onboarding Page (/onboarding)

### Purpose
Complete user profile if incomplete

### Fields
- Name
- Email
- Phone
- College
- etc.

### Flow
1. Fetch user data
2. If incomplete → show form
3. Submit → PATCH /users/:id
4. Redirect to dashboard

## 6.5 Event Detail Page (/events/[eventId])

This is the MOST IMPORTANT PAGE.

---

### Layout

Tabs:
- Overview
- Rules
- Submissions
- Leaderboard (optional)
- Phases (dynamic)

---

### 6.5.1 Overview Tab

- Event description
- Date/time
- Venue
- Judges

---

### 6.5.2 Registration Logic

If NOT registered:
- Show Register button
- Disable all other tabs

---

### 6.5.3 Phase Tabs (Dynamic)

Each phase = separate tab

Example:
- Phase 1
- Phase 2

---

### 6.5.4 Phase Tab Content

Each phase page includes:
- Problem Statement
- Instructions
- Venue
- Submission Form

---

### 6.5.5 Submission Form

Based on backend config:

- If type = URL → input field
- If type = file → file upload

---

### Submission Flow

1. User submits
2. Call POST /events/:id/submit
3. Show:
   - Success state
   - Submitted status

---

### 6.5.6 Access Control (CRITICAL)

Frontend must:

IF not registered:
→ disable all tabs except overview

IF accessLevel = ROUND1:
→ only allow Phase 1

IF phase not active:
→ disable tab

---

### 6.5.7 Leaderboard Tab

- Show rankings
- Only visible when enabled
