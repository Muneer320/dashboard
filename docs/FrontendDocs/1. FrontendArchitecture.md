# Frontend Architecture

## Stack

| Tool | Version | Role |
|---|---|---|
| React | 18 | UI framework |
| Vite | 5 | Dev server + bundler |
| React Router | v7 | Client-side routing |
| Plain `fetch` | — | API client (`src/lib/api.js`) |

No state management library. No CSS framework. All styling is inline React styles + a shared CSS token file (`src/styles/tokens.css`).

## API Client (`src/lib/api.js`)

Centralised fetch wrapper. All API calls go through `request()` which:

- Reads `VITE_API_BASE` env var (defaults to `/api/v1`)
- Attaches `Authorization: Bearer <token>` from localStorage
- Throws `ApiError(message, status, data)` on non-2xx
- Returns `null` on 204

**Token storage:**

| Key | Token type |
|---|---|
| `localStorage.ascent_token` | User JWT |
| `localStorage.ascent_admin_token` | Admin JWT |

**Exported namespaces:**

```js
auth          // login, me
adminAuth     // admin login, admin me
users         // get, patch, events, meals, myEvents
events        // list, get, register, myTeam, submit, submission, questions, setQuestions, rating, ...
schedule      // global, byDate, forEvent
announcements // list
feedback      // submit
credentials   // request
adminPanel    // stats, eventsStats, participants, lookup, myEvents, ...
qr            // scan
```

## Auth Flow

`UserAuthContext` reads `localStorage.ascent_token` on mount, calls `GET /auth/me` to validate, and exposes `{ user, ready, login, logout }`. The `ready` flag prevents flash-of-redirect on initial load. `RequireAuth` and `GuestOnly` wrappers in `App.jsx` use `ready` before rendering or redirecting.

## EventDetail + Submission Architecture

`EventDetail` (`dashboard.jsx`) is the main submission-facing page.

### Round normalisation

`event.rounds` JSONB is mapped to a normalised array via `normaliseRound(key, val)`:

```js
{
  key,        // "phase1"
  phaseNum,   // 1
  title,      // display name
  state,      // "live" | "upcoming" | "locked"
  timeLabel,  // formatted start time
  desc,
  phaseData,  // raw round object from API
}
```

State is derived from `is_active` + `is_locked` flags — not from timestamps — so the backend is always the source of truth.

### SubmissionPanel (`submission.jsx`)

Mounted once per selected phase (remounts via `key={eventId-phaseN}` on tab change).

Responsibilities:
1. Fetch questions: `GET /events/{id}/questions?phase=N`
2. Fetch existing submission: `GET /events/{id}/submission?phase=N` (pre-fills answers)
3. Determine submission state via `getSubmissionState()`:
   - `not-registered` → amber lock banner
   - `restricted` → red banned banner
   - `upcoming` → violet pending banner
   - `locked` → muted closed banner
   - `open` → active form
4. Render per-type input components
5. Client-side validate before submit (required, URL format, email format, word limits, declaration completeness)
6. Sanitise text answers (collapse whitespace, trim)
7. `POST /events/{id}/submit` with `{ phase, answers: [{question_id, answer}] }`
8. Show readonly view with "Edit ↺" on success; re-fetch submission

### Question type → input component mapping

| `question_type` | Component | Behaviour |
|---|---|---|
| `text` | `TextInput` | single-line, optional word limit counter |
| `text-long` | `TextInput` | `<textarea>`, 500-word default limit |
| `url` | `UrlInput` | `type="url"`, inline http/https format check |
| `email` | `EmailInput` | `type="email"`, inline regex check |
| `numeric` | `NumericInput` | `type="number"`, parsed as `parseInt` on submit |
| `mcq` | `McqInput` | pill buttons, single-select (click same to deselect) |
| `multi-choice` | `MultiChoiceInput` | checkbox buttons, multi-select |
| `declaration` | `DeclarationInput` | amber checkbox rows, must acknowledge all to submit |

## Submission State in Dashboard

The `Dashboard` registered-events list detects submission from the new per-phase shape:

```js
const hasSubmitted = submission && typeof submission === 'object'
  ? Object.values(submission).some(p => p?.submitted === true)
  : !!submission;  // legacy fallback
```

`EventDetail` tracks which phases have submissions in `submittedPhases: Set<string>` and updates it locally after each successful submit (avoids a full page refetch). A teal dot appears on the round tab for submitted phases.

## Design System

Tokens are in `src/styles/tokens.css`. Key variables:

- `--violet` (#7F77DD) — primary accent, live phases, selected elements
- `--teal` (#1D9E75) — success, submitted state
- `--amber` (#E8B974) — warnings, declarations
- `--glass` / `--glass-strong` — frosted glass card backgrounds
- `--f-display` (Syne) / `--f-body` (Montserrat) / `--f-mono` (JetBrains Mono)

Utility classes: `.glass`, `.glass-strong`, `.btn`, `.btn.primary`, `.btn.ghost`, `.btn.sm`, `.chip`, `.chip.violet`, `.chip.teal`, `.chip.amber`, `.eyebrow`, `.display`, `.input`, `.label`, `.fade-up`.
